## What shipped
Five changes, one commit each: Python 3.13, passlib to pwdlib, python-jose to PyJWT, google-generativeai to google-genai, typed response models. A sixth, a Settings bug found on the way, is in the same branch (see below).

## Why
Three unmaintained or deprecated libraries (passlib breaks on bcrypt 4.1+, python-jose is unmaintained, `google-generativeai` is deprecated and heavy), a Python version two releases behind, and four endpoints the frontends had to type by hand.

## How
| Area | Decision | Alternative rejected |
|---|---|---|
| Python | 3.13 everywhere: `.python-version` (CI reads it), `requires-python >=3.13,<3.15`, `python:3.13-slim-bookworm`, ruff `py313`, README. All dependencies resolved with 3.13 wheels | 3.12: no reason to stop short |
| Passwords | `pwdlib[bcrypt]`, `BcryptHasher(rounds=12)`, same `$2b$12$` format. Hashes made by passlib 1.7.4 verify (three fixture hashes are committed in the test). `bcrypt` pin removed; bcrypt 5.0.0 is installed | Argon2 for new hashes: would need a rehash-on-login path and gains nothing today |
| 72 bytes | bcrypt reads only 72 bytes. passlib cut longer input silently; bcrypt 5 raises. `_bcrypt_input` now truncates explicitly to 72 **bytes** (not characters), so a long-password user can still sign in. Tested: 80-char hash fixture, multi-byte password, over-long input never raises | Rejecting long passwords at login: locks out anyone who registered with one |
| App tokens | PyJWT, HS256 only (constant, not the `ALGORITHM` setting), `exp`, `sub` and `type` required. One decoder, `decode_app_token(token, type)` in `app/core/security.py`, used by `deps._user_from_token`, the WebSocket auth and the refresh/reset verifiers. No audience is passed, so PyJWT rejects any token carrying `aud` (admin tokens). Admin tokens keep their own derived key and `aud="admin"` | Per-call `jwt.decode` as before: three copies of the claim rules |
| Reset tokens | Now carry `type=password_reset` and the verifier requires it. Before, any signed token with a `sub` was accepted as a reset token. Tokens issued before this change stop working (no production data) | Leaving untyped |
| Unverified peek | `get_user_or_admin` reads `aud` with `jwt.decode(..., options={"verify_signature": False})`, then verifies with the matching decoder | |
| Gemini | `google-genai` async client (`client.aio.models.generate_content`), model `gemini-2.5-flash`, same prompts and fallbacks. Client is built on first use because the SDK refuses to construct without a key and the module-level service exists at import (CI has no key). The thread pool is gone. `print` became `log.exception`. The vitals route shares the module service instead of building one per request | A client per request: leaks connections |
| Response models | Describe today's shapes, add nothing, drop nothing. Money is `Decimal` so it still serialises as `"55000.00"`; offer-view nulls are Optional. A golden file maps every key to its JSON type and was generated from the untyped endpoints **before** the models existed | Reusing `BookingResponse`: floats for money and a different field set |
| Settings | `TRUSTED_PROXIES`, `BACKEND_CORS_ORIGINS`, `ADMIN_LOCKOUT_TIERS_MINUTES` are `Annotated[..., NoDecode]` so pydantic-settings no longer JSON-decodes them before the validators run. Empty, comma-separated and JSON all work (an empty lockout list keeps the default). `extra="ignore"` because `.env.example` also holds compose-only keys (`REDIS_PASSWORD`) that Settings forbade | Editing `.env.example`: the same file feeds docker compose |

## What's involved
- **Auth:** `app/core/security.py`, `app/api/deps.py`, `app/core/admin_security.py` (docstring), `scripts/capture_caregiver_flow.py` (uses `bcrypt` directly, no passlib).
- **AI:** `app/services/gemini.py`, `app/api/v1/endpoints/vitals.py`.
- **Config:** `app/core/config.py`.
- **Schemas:** `app/schemas/caregiver.py` (`VerificationStatusOut`, `FormOptionsOut`), `app/schemas/booking.py` (`CaregiverActionResponse`, `CaregiverActionBooking`), `app/schemas/admin_caregiver.py` (`ApplicationList`, `ApplicationDetail` and parts). Wired in `endpoints/caregiver.py`, `endpoints/booking.py`, `endpoints/admin_caregivers.py`.
- **Packaging:** `pyproject.toml`, `poetry.lock` (removed: passlib, bcrypt pin, python-jose, rsa, google-generativeai and its gRPC tree; added: pwdlib, bcrypt 5, google-genai), `.python-version`, `Dockerfile`, `README.md`.
- **Tests (new):** `test_password_hashing.py`, `test_app_tokens.py`, `test_gemini_service.py`, `test_response_shapes.py` + `golden/response_shapes.json`, `test_settings_env_file.py`. `test_access_auth.py` and `test_admin_auth.py` moved from jose to PyJWT for forging tokens.
- **Side effect:** `google-genai` pins `websockets<17`, so poetry moved it 17.1 to 16.1.1.

## Operate / roll back
- Revert the branch commits to roll back; there is no data change. Reset links issued before deploy stop working (users request a new one).
- New hashes are plain `$2b$12$` bcrypt, so rolling back to passlib still verifies them.
- Local environments need `poetry env use python3.13` then `poetry install`.

## Follow-ups
- [ ] Pydantic v1-style `@validator` and `class Config` remain in `config.py` and many schemas (deprecation warnings); move to `field_validator` / `model_config`.
- [ ] The caregiver action response still serves internal fields (`paystack_reference`, `*_kobo`, refund fields); the model now documents them, trimming is a contract change for the app.
- [ ] `GET /admin/caregivers/{id}` has no live capture in `docs/fe-captures/admin`; its shape is locked by the golden test only. Add it to the admin capture script when next touched.
- [ ] `datetime.utcnow()` is used widely and deprecated on 3.12+.
