## What shipped
The whole migration history is now **one migration**, `app/alembic/versions/0001_baseline.py`. It builds the full schema (30 tables) from an empty database. The test suite now builds its schema by running that migration, so tests exercise exactly what production gets.

## Why
- **The old history couldn't build an empty database.** It had 25+ migrations with two roots, and the vitals, access and FallGuard tables were never created by any migration. That forced two workarounds: a dev-only `init_local_db` bootstrap, and tests built from `create_all`.
- **There's no data to keep.** The owner confirmed on 2026-10-05 that no production database or records exist anywhere, so the history could be replaced outright.

## How
| Decision | Choice |
|---|---|
| Baseline | Autogenerated from the models (`alembic revision --autogenerate --rev-id 0001_baseline`) against an empty Postgres 16, then edited by hand |
| Hand-added SQL | The append-only trigger and function on `admin_audit_log` (autogenerate can't express it), plus dropping the four Postgres enum types on downgrade (Postgres keeps them after their tables are dropped) |
| `app/alembic/env.py` | Rewritten. It imports `app.core.config.settings` directly; the `sys.path` hack and the second settings instance are gone. **It no longer calls `load_dotenv()`**, which would have loaded a developer's real `.env` secrets into the test process once tests ran migrations. It escapes `%` in URLs for configparser and accepts a connection through `config.attributes["connection"]`. |
| Test schema | `conftest.py` drops and recreates `public`, then runs `alembic upgrade head` once per session. Tables are still truncated between tests. |
| Removed | All previous migration files; `scripts/init_local_db.py` and its hook in `boot/docker-run.sh`; `scripts/migrate_private_documents.py` and its 3 tests; the three per-migration transition tests (kobo, caregiver approval, dispatch), whose subjects are now part of the baseline |

## What's involved
- `app/alembic/versions/0001_baseline.py` (new); every other file in `app/alembic/versions/` deleted
- `app/alembic/env.py`
- `app/tests/conftest.py`, `app/tests/test_migrations.py` (new), `app/tests/test_access_documents.py`
- `boot/docker-run.sh`
- SOP notes in the access-control, money-in-kobo, secrets, caregiver-approval and jobs-and-dispatch SOPs; the plan; the checklist

## Verification
- **New tests in `test_migrations.py`:**
  - exactly one head;
  - on a fresh empty database: `upgrade head`, then `compare_metadata` against the models is **empty**, then `downgrade base` leaves only `alembic_version`, then `upgrade head` again;
  - `UPDATE` and `DELETE` on `admin_audit_log` are refused by the database ("append-only").
- **Manual check on Postgres 16:** `alembic check` reported "No new upgrade operations detected", and after the downgrade there were 0 enum types left.
- **Full suite:** every test now runs against the migrated schema.

## Operate
- **New environment:** `alembic upgrade head`. The container boot script does this automatically.
- **Next schema change:** `alembic revision --autogenerate -m "..."`. Review the file (autogenerate misses triggers, functions and enum drops), then add a test if it contains raw SQL. `test_migrations.py` catches any drift between models and migrations.

## Follow-ups
- None for the baseline itself.
- If a database was ever created from the old history (local dev volumes), recreate it: `docker compose down -v`.
